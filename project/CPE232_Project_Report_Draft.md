# **1. บทนำ (Introduction)**

ประเทศไทยมีรัฐธรรมนูญรวมทั้งสิ้น 20 ฉบับ นับตั้งแต่ปี พ.ศ. 2475 จนถึงปัจจุบัน ซึ่งถือว่าเยอะมากที่สุดเมื่อเทียบกับประเทศที่ปกครองในระบอบประชาธิปไตย รัฐธรรมนูญแต่ละฉบับสะท้อนบริบทการเมืองที่แตกต่างกัน ไม่ว่าจะรัฐบาลพลเรือน คณะรัฐประหาร หรือสภาเฉพาะกาล ดังนั้นโครงงานนี้มีเป้าหมายในการรวบรวม ดิจิทัลไลซ์ และวิเคราะห์รัฐธรรมนูญทั้ง 20 ฉบับในฐานะคลังข้อความ (Text Corpus) โดยใช้เทคนิค OCR, NLP, และ ML เพื่อตอบคำถามหลักว่า “รัฐธรรมนูญไทยเปลี่ยนแปลงอย่างไรตลอด 9 ทศวรรษ และการเปลี่ยนนี้สะท้อนประวัติศาสตร์การเมืองไทยอย่างไร?” นอกจากนี้ยังนำข้อมูล Structured จาก Constituteproject.org ซึ่งจัดทำดัชนีสิทธิ์ตามรัฐธรรมนูญของแต่ละประเทศ มาใช้เปรียบเทียบการคุ้มครองสิทธิในรัฐธรรมนูญไทยแต่ละฉบับเชิงปริมาณ

# **2. วัตถุประสงค์ (Objectives)**

* สร้างคลังข้อความ (Corpus) ของรัฐธรรมนูญ 20 ฉบับ โดยใช้ OCR, และการดึงข้อมูลจากไฟล์ pdf
* วิเคราะห์โครงสร้าง ได้แก่ จำนวนมาตรา ความยาว การแบ่งหมวด และความถี่ในการแก้ไขเพิ่มเติม
* หาการเปลี่ยนแปลงเชิงหัวข้อและภาษา ระหว่างแต่ละยุคการเมือง
* วัดและเปรียบเทียบสิทธิในรัฐธรรมนูญแต่ละฉบับ จากดัชนีของ constituteproject.org
* วัดความคล้ายคลึงระหว่างรัฐธรรมนูญแต่ละฉบับ
* สร้างโมเดล Machine Learning เพื่อวิเคราะห์โครงสร้าง โดยประยุกต์ใช้ความรู้จากวิชา CPE 232 Data Models ในทุกขั้นตอนที่สอดคล้องกับเนื้อหารายวิชา

# **3. แหล่งข้อมูลและเครื่องมือที่ใช้ (Data Sources and Tools)**

### **3.1 แหล่งข้อมูลรัฐธรรมนูญ**
ข้อมูลชั้นต้น (Primary Data) ที่ใช้ในโครงการนี้คือ รัฐธรรมนูญและธรรมนูญการปกครอง ของไทย ที่ประกาศใช้ในราชกิจจานุเบกษา ตั้งแต่ปี พ.ศ. 2475 ถึงปัจจุบัน รวมทั้งสิ้น 38 ไฟล์ (รวมรัฐธรรมนูญหลักและฉบับแก้ไขเพิ่มเติม)
* **จัดทำโดย:** สำนักวิชาการ สำนักงานเลขาธิการสภาผู้แทนราษฎร
* **แหล่งที่มา:** ระบบคลังสารสนเทศรัฐสภา ([https://catalog.parliament.go.th/dataset/12_01](https://catalog.parliament.go.th/dataset/12_01))
* **รูปแบบข้อมูลต้นฉบับ:** 
  * เอกสารที่เป็น PDF แบบ **รูปภาพ** (Image PDF) จำนวน 32 ฉบับ (พ.ศ. 2475 - 2548)
  * เอกสารที่เป็น PDF แบบ **ข้อความ** (Text PDF) จำนวน 6 ฉบับ (พ.ศ. 2550 - 2564)
* **สัญญาอนุญาต:** Creative Commons Attribution-NonCommercial-NoDerivatives 4.0 International License

### **3.2 ซอฟต์แวร์และเครื่องมือ (Software & Tools)**
ในส่วนของการจัดเตรียมข้อมูล (Data Preparation) ที่ได้ดำเนินการสำเร็จแล้ว มีการใช้เครื่องมือดังนี้:
* **Python / Jupyter Notebook:** เครื่องมือหลักในการเขียนและรันท่อข้อมูล (Data Pipeline)
* **Typhoon OCR API:** โมเดลประมวลผลและสกัดอักษรจากภาพที่มีประสิทธิภาพสูงสำหรับภาษาไทย
* **PyMuPDF (`fitz`) / pdfplumber:** ไลบรารีสำหรับดึงข้อความจากไฟล์ PDF โดยตรง
* **Pandas / JSON:** เครื่องมือในการจัดรูปแบบและจัดการโครงสร้างข้อมูลให้เป็น Structured Data ตามหลัก Data Models

# **4. การเตรียมและประมวลผลข้อมูล (Data Preparation & Structuring)**

เนื่องจากข้อมูลเริ่มต้นอยู่ในรูปแบบที่ไม่มีโครงสร้าง (Unstructured Data) และมีความแตกต่างกันตามช่วงเวลาของไฟล์เอกสาร คณะผู้จัดทำจึงแบ่งกระบวนการในส่วนนี้ออกเป็น 2 ขั้นตอนหลัก ได้แก่ การสกัดข้อมูล (Extraction) และการจัดโครงสร้าง (Structuring)

### **4.1 ขั้นตอนแปลงเอกสาร PDF ให้เป็นข้อมูลข้อความ (Data Extraction)**
กระบวนการนี้ทำหน้าที่สกัดข้อความดิบออกจากไฟล์เอกสารกฎหมาย โดยประยุกต์ใช้วิธีที่เหมาะสมกับประเภทของ PDF:

1. **การแปลงข้อมูลผ่าน OCR (Optical Character Recognition) สำหรับไฟล์รูปภาพ:**
   * **เป้าหมาย:** เอกสาร 32 ฉบับ ตั้งแต่ปี พ.ศ. 2475 ถึง 2548 ซึ่งเป็นภาพถ่ายหรือการสแกนเอกสารเก่า
   * **วิธีการ:** ใช้ **Typhoon OCR 1.5** ผ่าน API เนื่องจากถูกฝึกสอนมาให้รองรับตัวอักษรและภาษาไทยได้ดีเยี่ยม โดยส่งไฟล์ภาพเข้าไปประมวลผลทีละหน้า เพื่อแปลงภาพเป็นข้อความดิจิทัล

2. **การสกัดข้อมูลโดยตรงสำหรับไฟล์ข้อความ (Text Extraction):**
   * **เป้าหมาย:** เอกสาร 6 ฉบับ ตั้งแต่ปี พ.ศ. 2550 ถึง 2564 ซึ่งถูกสร้างจากโปรแกรมพิมพ์เอกสาร
   * **วิธีการ:** ใช้ **PyMuPDF (`fitz`)** เป็นตัวเลือกหลักเนื่องจากเสถียรและแม่นยำ และใช้ **pdfplumber** เป็นตัวสำรอง (Fallback) ในกรณีที่เกิดข้อผิดพลาดในการดึงข้อความ ซึ่งวิธีนี้รวดเร็วและใช้เวลาเพียงหลักนาที

### **4.2 ขั้นตอนจัดโครงสร้างและทำความสะอาดข้อมูล (Data Structuring & Cleaning)**
เมื่อได้ข้อความดิจิทัลมาแล้ว ข้อมูลยังคงมีความซับซ้อนและมีสิ่งเจือปน จึงต้องนำมาทำความสะอาดและจัดโครงสร้างใหม่ให้อยู่ในรูปแบบ **Structured Data (JSON Schema)** ซึ่งสอดคล้องกับหลักวิชา CPE232 Data Models:

1. **การทำ Normalization และจัดการอักขระ:**
   * ปรับรหัสอักขระ (Encoding) ให้เป็นมาตรฐาน Unicode NFC Form 
   * ทำการแปลงตัวอักษรภาษาไทยที่มีการเข้ารหัสแบบพื้นที่ใช้งานส่วนตัว (Private Use Area: PUA) จากฟอนต์ยุคเก่า (เช่น AngsanaUPC) ให้กลับมาเป็น Unicode มาตรฐาน

2. **การกำจัดข้อมูลส่วนเกิน (Data Cleaning):**
   * ทำการตัดข้อความส่วนหัวและส่วนท้ายของเอกสาร (Header/Footer) เช่น คำว่า "ราชกิจจานุเบกษา" "เล่ม" "ตอนที่" และ "หน้า" ด้วยฟังก์ชัน Regular Expression (RegEx) เพื่อไม่ให้รบกวนความหมายในกระบวนการ Machine Learning

3. **การจัดทำโครงสร้างข้อมูล (JSON Structuring):**
   * จัดเก็บข้อมูลที่ได้เป็น Object ในรูปแบบ JSON โดยออกแบบ Model ให้มี Metadata ครบถ้วน ได้แก่: `id`, `year_th` (ปี พ.ศ.), `year_ce` (ปี ค.ศ.), `name_short`, `source_type` (Image/Text PDF), `processing_method`, `era` (ยุคทางการเมือง), `regime_type`, `pages` (ข้อมูลรายหน้า) และ `full_text` 
   * การจัดโครงสร้างเช่นนี้ช่วยให้ข้อมูลพร้อมถูกนำเข้าสู่ Pandas DataFrame ในขั้นตอนการวิเคราะห์ต่อไป

# **5. แผนการดำเนินงานในระยะถัดไป (Future Work / Next Steps)**

ในส่วนของกระบวนการวิเคราะห์ การสร้างแบบจำลอง และการนำเสนอผลิตภัณฑ์ ซึ่งเป็นหน้าที่ที่ต้องรับผิดชอบร่วมกับสมาชิกท่านอื่นในกลุ่ม มีแผนการดำเนินงานดังต่อไปนี้:

1. **Exploratory Data Analysis (EDA):** สำรวจและสร้างความเข้าใจในชุดข้อมูล เช่น การหาความถี่ของคำ จำนวนคำเฉลี่ยต่อมาตรา
2. **Text Processing & Tokenization:** ประยุกต์ใช้ PyThaiNLP เพื่อตัดคำภาษาไทย, ลบ Stopword, และแปลงเลขไทยเป็นเลขอารบิก
3. **Feature Extraction:** แปลงข้อความให้เป็นตัวเลขผ่าน Bag-of-Words, TF-IDF และ Word Embeddings (WangChanBERTa)
4. **Machine Learning Modeling:** ใช้การเรียนรู้แบบไม่มีผู้สอน (Unsupervised Learning) ในการทำ Topic Modeling เพื่อดึงหัวข้อหลักในแต่ละรัฐธรรมนูญ และวัดค่า Document Similarity
5. **Data Visualization:** นำเสนอผลลัพธ์ผ่านกราฟ เช่น Timeline, Heatmap เพื่อเปรียบเทียบดัชนีสิทธิ และกราฟเครือข่ายความสัมพันธ์
6. **Product Development:** จัดทำข้อมูลให้อยู่ในรูปแบบ Open Dataset (Hugging Face / Kaggle) และพัฒนา Web Application เพื่อเผยแพร่ให้สาธารณชนเข้าถึงได้ง่าย

# **6. ปัญหา อุปสรรคที่พบ และแนวทางแก้ไข**

ในกระบวนการจัดเตรียมข้อมูล (Data Preparation) ซึ่งเป็นขั้นตอนที่ดำเนินการเสร็จสิ้นแล้ว พบปัญหาที่สำคัญและได้ดำเนินการแก้ไขดังนี้:

**1. รูปแบบสระอำที่ไม่สมบูรณ์ในเอกสารรัฐธรรมนูญ (สระอำแยกร่าง)**
* **ปัญหา:** ในไฟล์เอกสารแบบ Text PDF (เช่น ปี 2550 ถึง 2564) ซึ่งใช้ระบบฟอนต์แบบเก่า มีการเข้ารหัสตัว "สระอำ" ด้วยการใช้พยัญชนะเว้นวรรค (Zero-width space) ประกอบกับสระอา ส่งผลให้เมื่อสกัดข้อความออกมา คำว่า "จำนวน" ถูกแยกกลายเป็น "จ านวน" ซึ่งกระทบต่อการวิเคราะห์คำอย่างรุนแรง
* **การแก้ไข:** ในส่วนที่ 4.2 ได้มีการเพิ่มกระบวนการ Post-processing โดยใช้ฟังก์ชัน `_fix_sara_am()` ซึ่งใช้ Regular Expression ในการตรวจจับแพทเทิร์นพยัญชนะที่ตามด้วยเว้นวรรคและสระอา แล้วแปลงกลับเป็นสระอำให้ถูกต้องสมบูรณ์

**2. ข้อความรบกวนจากราชกิจจานุเบกษา**
* **ปัญหา:** เอกสารทุกหน้าจะมีข้อความอ้างอิงและเลขหน้าแทรกอยู่เสมอ ซึ่งจะทำให้จำนวนคำ (Word count) ผิดเพี้ยน และรบกวน Topic Model
* **การแก้ไข:** ได้มีการออกแบบลิสต์ของ RegEx Patterns (เช่น `_remove_headers()`) เพื่อตัดข้อความเหล่านี้ทิ้งก่อนการจับกลุ่มข้อมูลเข้าด้วยกัน
